Pre-identified Risks
--------------------

1. **``.gitkeep`` in ``msg/``**: A placeholder ``.gitkeep`` file exists in the
   ``msg/`` directory. ``rosidl_generate_interfaces`` should ignore non-``.msg``
   files, but if it causes issues, delete it before building.

2. **Non-standard workspace layout**: The package lives under
   ``lifecore_ros2/lifecore_state/``, not a standard ``src/`` colcon layout.
   Using ``--base-paths`` is required. If this fails, create a symlink:

   .. code-block:: bash

       mkdir -p /workspaces/lifecore_ros2_ws/src
       ln -sf /workspaces/lifecore_ros2_ws/lifecore_ros2/lifecore_state/lifecore_state_msgs \
              /workspaces/lifecore_ros2_ws/src/lifecore_state_msgs
       colcon build --packages-select lifecore_state_msgs

3. **Duplicate constants**: ``TYPE_*`` constants are duplicated across
   ``StateDescriptor``, ``StateSample``, and ``StateCommand`` (Sprint 18.8
   decision: Option A, embedded constants). These live in separate message
   namespaces and should not cause build collisions. If they do, the fix is
   to extract a shared ``StateType.msg`` (Option B from Sprint 18.8).

4. **``DIR_OUT``/``DIR_IN`` naming**: StateDescriptor uses ``DIR_OUT=0``,
   ``DIR_IN=1`` (2 values). The Sprint 17 RFC originally mentioned 5 direction
   values (UNKNOWN, INPUT, OUTPUT, INOUT, INTERNAL). The current ``.msg`` has
   only 2. This is a semantic drift that should be noted but does not block
   build validation.

5. **Missing ``DIR_*`` in sample/command**: ``StateSample`` does not carry
   direction constants; it references the descriptor which carries them. This
   is correct architecture but worth documenting.
